# DeepHunter Docker - Change Log

## [Unreleased]

### Security
- **Authlib upgraded to >=1.6.9** — fixes CVE-2026-27962 (CRITICAL: JWK Header Injection authentication bypass).
- **`.trivyignore` added** — acknowledges CVE-2025-7458 (libsqlite3-0, no Debian 12 fix, SQLite unused at runtime) and CVE-2023-45853 (zlib1g minizip, Debian will_not_fix).

### Fixed
- **SARIF upload in CI** — added `actions: read` permission to the `security-scan` job and upgraded `codeql-action` from v3 to v4 to fix "Resource not accessible by integration" errors.

### Added
- **Docker Hub publishing pipeline** — GitHub Actions workflow now builds, tests, scans, publishes to Docker Hub, signs the image with cosign (keyless via GitHub OIDC), and attaches a CycloneDX SBOM on version tag pushes (`v*`).
- **Image signing with cosign** — every published image is signed using Sigstore keyless signing; consumers can verify provenance with `cosign verify`.
- **SBOM generation** — CycloneDX SBOM generated by Syft, attached to the image and uploaded as a workflow artifact.
- **Docker Hub README** (`DOCKER_HUB_README.md`) — standalone repository description automatically synced to Docker Hub via `peter-evans/dockerhub-description`.
- **MIT LICENSE file** — added at the repository root for enterprise trust and OCI label compliance.
- **`make push` target** — manual image push to Docker Hub; requires `DOCKER_REGISTRY` to be set.
- **`DEEPHUNTER_IMAGE` variable** — `docker-compose.yml` now uses `${DEEPHUNTER_IMAGE:-deephunter:latest}`, allowing pull-based deployments without editing the Compose file.
- **`DOCKER_REGISTRY` variable** — `build.sh` supports an optional registry prefix for tagging images destined for Docker Hub or other registries.
- **Docker Hub documentation** section in `README.md` — pulling, image verification, publishing workflow, and required GitHub secrets.
- **Git secret-string guard**: pre-commit and pre-push hooks that block commits/pushes containing forbidden strings (case-insensitive). Patterns are configurable via `.githooks/forbidden-patterns.txt` (gitignored, local-only); a committed `.example` template is provided. Activate with `make setup-hooks`. The `install` target now includes hook setup automatically.
- **Custom Root CA trust**: place `.crt` files in `resources/root_ca/` to have them trusted by the system and Python at build time (corporate proxies, internal services)
- `SSL_CERT_FILE` and `REQUESTS_CA_BUNDLE` environment variables so Python `requests`/`urllib3` use the system CA bundle
- `.gitignore` rule to prevent private `.crt` files from being committed
- `.dockerignore` rules to exclude private key material (`*.key`, `*.pem`, `*.p12`, `*.pfx`) from the build context

### Changed
- **Dockerfile labels migrated from `org.label-schema.*` to OCI `org.opencontainers.image.*`** — recognized by Docker Hub, GHCR, and all major registries for metadata display.
- **CI/CD workflow rewritten** — enhanced with publish, sign, and SBOM jobs; Trivy now fails on CRITICAL vulnerabilities and uploads SARIF to GitHub Security tab; version tag triggers full publish pipeline.
- **`.dockerignore` hardened** — now excludes `.github`, `.githooks`, `examples`, `Makefile`, `Dockerfile.debug`, `.env`, `.env.example`, and `LICENSE` from build context.
- **Migrated from `docker-compose` v1 to `docker compose` v2 (CLI plugin)** across Makefile and all documentation. The legacy standalone `docker-compose` binary is no longer supported — it does not honour `start_period` in health checks, causing intermittent startup failures. Minimum required version is **Docker Compose v2.17+**.
- `check-requirements.sh` now verifies Docker Compose v2 plugin presence and minimum version.
